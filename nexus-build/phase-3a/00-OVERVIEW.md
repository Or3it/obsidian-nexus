# Phase 3A — Project Hub (Static Home Base)

## Goal

Turn Obsidian into the home base for all your projects. A glass wall of auto-discovered project cards you can scroll, click into for detail, and chat about — all without leaving Obsidian. Summary-level knowledge, generated free via the Claude Code subprocess. This is the foundation; the live/run layer is Phase 3B.

## What 3A delivers

- Auto-discovery of projects in `~/Documents/`, with a human review/approve gate before anything is indexed.
- A one-paragraph summary + stack + status + category per approved project, written by Sonnet (subprocess, free) and stored as vault notes in `Projects/`.
- A dashboard view inside Obsidian: a scrollable glass wall of all project cards.
- Click-in detail: summary, file tree, rendered README, git status — all inside Obsidian.
- Handoff buttons: open the project in VS Code / reveal in Finder, for when you need to leave.
- A project-aware chat: the existing Nexus chat, fed approved project summaries, so it can answer "what does sample-scraper do?" / "which projects use Flask?"
- Liquid-glass styling throughout, building on the `.nexus-glass` token.

## Deferred to Phase 3B (designed-for, not built here)

- Per-project run command + start/stop with output streamed into Obsidian.
- Live web-UI previews embedded in cards (only meaningful once projects can run).
- Cards in 3A reserve the preview slot but show the details layout / a placeholder.

## Architecture recap

```
~/Documents scan → candidates → YOU approve
   → Sonnet summarizes approved (subprocess, free)
      → Projects/<name>.md note (frontmatter: name, path, stack, status, category, run_command?, last_indexed; body: summary)
         → Dashboard view reads Projects/*.md → glass card wall
            → click card → detail view (summary, tree, README, git) inside Obsidian
               → open-in-VSCode / reveal-in-Finder handoff buttons
         → project-aware chat injects approved summaries into context
```

Backend (T01-T03) is the spine. Frontend (T04-T07) is the visible part. Polish + acceptance (T08) last.

## Project-note schema (`Projects/<slug>.md`)

```yaml
---
name: Sample Project
slug: sample-project
path: /Users/you/Documents/Sample project
stack: [python, flask, telegram]
status: active            # active | stale | archived (inferred from git mtime)
category: trading         # trading | ai-tooling | scraping | worship | other
run_command: null         # filled in Phase 3B
preview: null             # screenshot path or localhost URL; Phase 3B
last_indexed: 2026-05-31T...
discovered_at: 2026-05-31T...
---

<one-paragraph summary generated by Sonnet>
```

The vault is the store. The dashboard reads these notes; you can open/edit them like any note; removing a project deletes its note (never the real folder).

## Acceptance criteria (3A)

1. `pytest tests/` passes (existing + new).
2. Discovery finds the active `~/Documents` projects and returns them as candidates without reading file contents.
3. Approving a candidate produces a `Projects/<slug>.md` note with a real Sonnet-generated summary, detected stack, inferred status/category.
4. The dashboard renders a scrollable glass wall of all indexed project cards.
5. Clicking a card opens a detail view (summary, file tree, README, git status) inside Obsidian.
6. Open-in-VS-Code and reveal-in-Finder work from the detail view.
7. The chat, when project-aware, correctly answers a cross-project question using the summaries.
8. Removing a project deletes its note and card, leaving the real folder untouched.

## Constraints carried from prior phases

- One ticket per Claude Code session; read CLAUDE.md + ticket + OPEN_QUESTIONS.md first; commit locally; stop at Definition of Done.
